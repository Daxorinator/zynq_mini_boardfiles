# Hand-written PS7 init (no Vivado)

Replaces the Vivado-generated `ps7_init_gpl.c` for the ZYNQ MINI (XC7Z010, 33.333 MHz PS clock, 512 MB DDR3 x16, MT41J256M16 at 533 MHz).

- `ps7_open.c/.h`  the init: DDR I/O pads, 54 MIO pins (as a pin table by function), PLLs and clocks computed from the board
  parameters at the top, DDR controller, peripherals (UART1, QSPI, USB PHY reset), post-config. Silicon rev 3.x only.
- `ps7_ddr_table.inc`  the DDR controller register block as named-field C (GENERATED by `gen_ddr_table.py` from the Vivado
  reference model). Timing and PHY values are carried over from the Vivado output, board-tuned values (PHY slave ratios) are opaque.
- `ps7_hw.c`  target glue (poll with timeout, ms delay on the Cortex-A9 global timer).
- `decode.py` -> `ps7_model.json`/`ps7_model.md`  decodes the Vivado tables into operations with named fields (the REFERENCE only).
- `verify.sh`  compiles the init on the PC with every register access logged and compares the sequence with the Vivado tables.
  Result: 210 init operations + 4 post-config operations IDENTICAL (also checked that deliberate one-bit errors are caught).
- `../baremetal/`  bare-metal DDR test using this init, driven by `../../tests/run_ddr_test.sh`.

Honest limits: the DDR PHY tuning (read/write DQS ratios, gate timing, DCI drive) is not derived, it is the board-tuned Vivado
result; nothing public computes it. The PLL filter row (res/cp/lock count) is only known for the three dividers used (30, 32, 40).
Register names for the DDRC were recalled from the TRM index; check against UG585 before publishing.

## Results (2026-11)
1. Trace equivalence on the PC: 210 + 4 operations identical to the Vivado tables (verify.sh).
2. Bare-metal test on the board with this init (no Vivado code in the image): ps7_open_init() success, PLL/DDRC status
   registers identical to the Vivado run, 511 MiB DDR3 test, 0 errors in all three patterns.
3. Built into the U-Boot SPL (board/xilinx/zynq/zynq-zynqmini/ps7_init_gpl.c is now a thin wrapper over ps7_open.c; the
   Vivado file is kept as ps7_init_gpl_vivado.c.bak): staged test from U-Boot, then cold boot via the boot ROM from the SD
   card: SPL -> U-Boot -> PYNQ Linux. /boot/BOOT.BIN = ~/ps3/final2/BOOT.BIN (md5 9cd330b7dcde77d41b22081298057467).
   Fallbacks on the card: BOOT.BIN.vivado_init (open SPL with the Vivado init, md5 4600c3e6...), BOOT.BIN.orig (vendor).
Still derived from Vivado output rather than independent: the DDR PHY tuning and DDRC timing values, the PLL filter rows for
dividers 30/32/40, and (outside ps7_init) U-Boot's device tree pcw.dtsi, which PetaLinux generated from the Vivado hardware export.
